## 요약 — 데이터 흐름 5줄

1. **표**: `wg_group`(그룹) · `wg_item`(종목과 구분행을 한 표에 두고 `sort_no` 순서로 섹션을 만든다) · 테마 변수 `wg_group_var` → `mv_var` → `mv_daily`. 고정 그룹 셋(★보유종목·★Top-Pick·★최근조회)은 **DB 행이 없다**. 각각 `pf_position`·`pf_watchlist`·`dt_pool`을 읽을 때마다 비춘다.
2. **클래스**: `classes/Wg.class`(관심그룹 DB 전담) · `classes/Mv.class`(변수 DB와 네이버 시장지표 수집).
3. **API**: `/stock/api.php?module=wg&action=…`(`stock/lib/wgroup_api.php`) · `module=mv`(`stock/lib/mv_api.php`). 응답은 JSON `{ok, data, error}`이고, 변경은 **POST + 같은 출처(Origin)**만 받는다.
4. **화면**: `/stock/index.php?mode=wgroup&g=<key|id>` → `stock/lib/wgroup.php`의 `pf_page_wgroup()`. 첫 화면은 서버가 그려 넣고, 그 뒤 동작은 JS가 위 API를 부른다.
5. **시세·배지·보유는 저장하지 않는다.** 읽을 때 `Wg::decorate()`가 붙인다: `all_stock_info`(현재가 — 보고 있는 그룹은 장중 10초마다 키움) + `quant_badge_many()`(배지 판정) + `Dt`(보유·1분봉 원장). 행 모양은 단타와 같은 `style/stockrow.js`가 그린다.

### 설계에 가장 크게 걸리는 사실 셋 (자세한 것은 해당 질문)
- **임포터의 «v0»이 이미 있다.** 「그룹 관리 · 일괄등록」 모달에 마크다운 표 붙여넣기 → 미리보기 → 담기가 있다. 제목줄은 구분행+방향으로, 표 칸은 메모로 들어간다(Q17 · 오늘 서버에서 견본으로 실측).
- **기준일은 API로 지정할 수 없다.** 기준가를 저장하면 `base_date = CURDATE()`로 고정된다(Q8).
- **여러 단계를 묶는 트랜잭션이 없다. 바깥에서 감싸기도 어렵다** — 내부 메서드가 각자 `beginTransaction()`을 하기 때문이다(Q16 · Q26).

- Composer: `composer.json`·`vendor/` 없음(실측). 레포 규칙상 외부 PHP 라이브러리 없이 순수 PHP로 짠다.

**Q5 ★** 그룹 종류와 순서
- `★보유종목`·`★Top-Pick`·`★최근조회`와 `1 스마트폰`·`2 원자재`·`3 환율`은 무엇으로 구분되나 (시스템/사용자, ★의 의미, 자동 생성 여부)
- 번호·순서는 어디에 어떻게 저장되나. 새 그룹을 만들면 어디에 붙나

> **답:** ★ = **코드 상수로 정의된 고정 그룹**(DB 행 없음 · 음수 id · 편집 불가). 숫자 = 내가 만든 그룹(`wg_group` 행)의 화면 서수. 숫자 자체는 저장하지 않고 `sort_no` 순서에서 나온다. 새 그룹은 맨 아래(`MAX(sort_no)+1`)에 붙는다.

- 고정 그룹: `Wg::BUILTIN`(`Wg.class:47-55`) — `G_HELD=-1 (key held, 보유종목)` · `G_TOP=-2 (top, Top-Pick)` · `G_RECENT=-3 (recent, 최근조회)`. 자동 «생성»이 아니라 **읽을 때마다 원천에서 비춘다**(`codes()` `:328-352`, `builtinRows()` `:498-536`).
  - 보유종목 = `pf_position.status <> 'closed'`(`Dt::heldCodes()`/`heldList()`)
  - Top-Pick = `pf_watchlist`(담은 순) **중 보유하지 않은 것**
  - 최근조회 = `dt_pool` active(단타 화면에서 열어 3초 머문 종목 · 본 순)
  - 잠금: 서버 `wgroup_api.php:51-53`(item_add·sep_add·bulk_base·item_reorder·table_add 거절)과 화면 `lockTools()`. 행 id도 음수 임시값이라 고치는 API에 넘겨도 대상이 없다. 고정 그룹에서 나가는 길은 「내 그룹에 복사」뿐이다(`copyFromBuiltin()` `:544`).
- 내 그룹: `wg_group` 행. 앞의 `1·2·3`은 **화면이 매기는 서수**이고 Alt+1~9 단축키와 같다(`wgroup.php:657-680`의 `renderGroups()`, `no++`).
- 순서 저장: `wg_group.sort_no`(현재 1·2·3). 목록 SQL은 `ORDER BY g.sort_no, g.id`(`Wg.class:139-144`). 고정 그룹은 늘 맨 위다(`groupsAll()` `:154-169`).
- 새 그룹(`Wg.class:263-270`):
  ```php
  $no = (int)$this->pdo->query("SELECT COALESCE(MAX(sort_no), 0) + 1 FROM wg_group")->fetchColumn();
  $st = $this->pdo->prepare("INSERT INTO wg_group (name, sort_no) VALUES (?, ?)");
  ```
- 이름 규칙(`cleanName()` `:242-260`): 공백을 접은 뒤 1~30자. **UNIQUE**이고 고정 그룹 이름(보유종목·Top-Pick·최근조회)은 쓸 수 없다.
- 순서 변경: `group_reorder` → 보낸 id 순서로 1..N을 다시 매긴다(트랜잭션 · `:287-301`). 빠진 id는 원래 순서대로 뒤에 붙는다(`mergeOrder`).

**Q6 ★** 구분행 (`+ 구분행`, 예: '환율 상승(원화 약세) 때 유리')
- 별도 테이블인가, 그룹-종목 테이블의 특수 행인가
- 종목의 구분행 소속은 무엇으로 정해지나 (FK / 순서상 위치)
- 구분행 속성 전부와 의미 (제목, `↑`·`↓ 유리` 칩, 오른쪽 숫자 8·10, 접힘, 색 등)

> **답:** **`wg_item`의 특수 행**이다(`item_type='sep'`, `stock_code` NULL). 종목의 소속은 **순서상 위치**로 정해진다(FK 없음). 정렬 순서에서 그 구분행 아래부터 다음 구분행 앞까지의 종목이 그 섹션이고, 첫 구분행 위의 종목은 소속이 없다.

- 소속 판정 코드: 서버 `Wg::bulkBase()`(`Wg.class:750-762`)와 화면 `sectionIds()`(`wgroup.php:756-763`)가 같은 방식으로 센다.
- 속성:

|---|---|---|

**Q7 ★** 중복 규칙: 같은 종목이 여러 그룹에 들어갈 수 있나 / 같은 그룹 안에서 중복(다른 구분행)은 되나. 그룹-종목의 고유키는 무엇인가.

> **답:** 여러 그룹에는 **된다**. 같은 그룹 안에서는 **한 번만**이라, 같은 종목을 두 구분행에 동시에 둘 수 없다. 고유키는 `UNIQUE KEY uq_group_stock (group_id, stock_code)`이다.

- 행 PK는 `wg_item.id`(AUTO_INCREMENT)다. 구분행은 `stock_code`가 NULL이라 UNIQUE에 걸리지 않으므로 한 그룹에 여러 개 둘 수 있다.
- 코드에서도 막는다: `itemAdd()`는 이미 있는 종목을 `dup`으로 돌려준다(`Wg.class:605`). `parseTable()`은 붙여넣은 글 안에서 같은 종목이 두 번째 나오면 조용히 무시한다(`:947` `$seen`). `transfer()`도 대상 그룹에 있으면 `skip`이다.
- 실측: 지금 둘 이상의 그룹에 든 종목은 0건이다.

**Q8 ★** 기준가
- 저장 위치와 단위 (그룹-종목별인가 종목별인가), 기준일 저장 여부
- 빈 값('입력' 표시) 처리
- `기준가 = 현재가 (전체)`, `기준가 지우기`의 정확한 동작
- `기준대비` 계산식

> **답:** `wg_item.base_price` INT UNSIGNED(**원 · 정수 1~100,000,000**)와 `wg_item.base_date` DATE에 둔다. **그룹-종목별**이다(같은 종목도 그룹마다 다르다 · CLAUDE.md:599 규칙 3). ★**기준일은 API로 지정할 수 없다** — 저장하는 순간 `CURDATE()`가 들어간다.

- 저장(`Wg::itemUpdate()` `Wg.class:700-709`):
  ```php
  // base_price 가 null/'' 이면 지우기
  UPDATE wg_item SET base_price = NULL, base_date = NULL WHERE id = ?
  // 숫자면 — cleanBase(): 숫자만 남겨 1 ~ 100,000,000 범위 검사(:675-683)
  UPDATE wg_item SET base_price = ?, base_date = CURDATE() WHERE id = ?
  ```
  기준일이 오늘이 아닌 값으로 들어가는 길은 `transfer()`(복사·이동)와 `copyFromBuiltin()`(Top-Pick의 담은 날)뿐이다. 둘 다 **원래 행의 값을 복사**한다.
- 빈 값: NULL이면 화면 CSS가 `'입력'`을 그린다 — `.wg-r .bs:empty::before{content:'입력'}`(`wgroup.php:184`). 고정 그룹에서는 `'—'`다(`:177`). 칸을 누르면 입력칸이 뜨고(천단위 콤마 · Enter 저장 · Esc 취소 · ↓ 다음 종목), 비우고 Enter를 누르면 지워진다(`editBase()` `:976-1018`).
- 고정 그룹: Top-Pick의 기준가 = `pf_watchlist.added_price`(담을 때 가격 · 읽기 전용)이고 기준일 = 담은 날이다. 보유종목·최근조회에는 기준가가 없다.
- **기준가 = 현재가 (전체)** → `bulk_base {group_id, mode:'current', section_id:0}` → `Wg::bulkBase()`(`:750-791`):
  - 그 그룹의 모든 종목 행(`section_id`가 있으면 그 섹션만)의 기준가를 `round(all_stock_info.stock_price)`, 기준일을 오늘로 **덮어쓴다**(기존 기준가가 있어도 덮는다).
  - 현재가가 없거나 범위 밖인 종목은 건너뛴다. 트랜잭션 안에서 돈다.
  - 장중에 누르면 «그 순간의 시세표 값»이지 종가가 아니다.
  - 버튼은 한 번 누르면 3초 동안 「정말?」로 바뀌는 확인 방식이다(`arm()` `:573` · `confirm()` 금지 규칙).
- **기준가 지우기** → `mode:'clear'` → 대상 행의 `base_price`·`base_date`를 NULL로 만든다(단일 UPDATE · `:765-771`).
- **기준대비(%)** = (현재가 − 기준가) ÷ 기준가 × 100. 저장하지 않는 파생값이다(`wgroup.php:550`).
  ```js
  function vsBase(it){ return (it.base && it.price) ? (it.price - it.base) / it.base * 100 : null; }
  ```
  현재가 = `all_stock_info.stock_price`(Q13). 둘 중 하나라도 없으면 `—`이고, 기준대비순 정렬에서는 맨 아래로 간다.

**Q9** 메모 필드: 종목 행 단위 메모가 있나, 그룹 단위 설명·메모가 있나. 행의 보조 텍스트('10일 3,781' 등)는 어디서 오나.

## C. 종목·가격 데이터

**Q12 ★** 종목 마스터: 테이블명, 컬럼(코드·종목명·시장·상태), 갱신 주기·출처, 영문자가 섞인 코드 지원 여부, 상장폐지·거래정지·우선주 처리.

> **답:** 마스터 표는 `stock_master`이고 단일 진입점은 `classes/StockName.class`다. KRX 전종목에서 매일 13:05(T+1)에 갱신한다. 영문 코드는 **된다**. **상태 컬럼은 없다** — 상장폐지는 `last_seen`이 멈추는 것으로, 거래정지는 `krx_amt.vol=0`으로 드러난다.

```sql
CREATE TABLE `stock_master` (
  `code` varchar(10) NOT NULL COMMENT '6자리 종목코드',
  `name` varchar(80) NOT NULL DEFAULT '' COMMENT '거래소 종목명 (KRX)',
  `market` varchar(10) NOT NULL DEFAULT '' COMMENT 'KOSPI / KOSDAQ',
  `first_seen` date DEFAULT NULL COMMENT 'krx_daily 에서 처음 본 거래일',
  `last_seen` date DEFAULT NULL COMMENT 'krx_daily 에서 마지막으로 본 거래일 — 멈추면 상장폐지·거래정지 의심',
  `updated_at` datetime NOT NULL DEFAULT current_timestamp() ON UPDATE current_timestamp(),
  PRIMARY KEY (`code`),
  KEY `idx_name` (`name`),
  KEY `idx_last` (`last_seen`)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COLLATE=utf8mb4_general_ci COMMENT='종목 마스터 — KRX 전종목 · classes/StockName.class 가 주인 (2026-09-04)'
```

- 실측: 2,783행(KOSDAQ 1,839 · KOSPI 944) · 최신 `last_seen` 2026-10-23 · 이름 중복 0건.
- 갱신: 크론 `dart_krx`(평일 13:05) 끝에서 `StockName::sync()`(`StockName.class:89-134`)가 `krx_daily`(KRX 전종목 최근 10거래일)를 UPSERT한다. 외부 콜은 0이다. **지우지 않는다.** 사명이 바뀌면 더 최신 날짜의 이름이 덮는다.
- 이름 읽기: `StockName::many($pdo, $codes)`(`:157-191`)가 사슬 `stock_master → all_stock_info → krx_daily → dart_corp_code → pf_stock → dt_pool`을 위에서부터 찾는다(`CHAIN` `:50-63`). 관심그룹은 종목명을 저장하지 않고 볼 때마다 이 사슬로 잇는다(`Wg.class:12`).
- 영문 코드: 89건(예 `0001A0` 덕양에너젠 · `0004V0` 엔비알모션 — 신규상장·인적분할). `wg_item.stock_code` CHAR(6)에 들어가고, 파서 정규식 `\d{4}[0-9A-Za-z]{2}`(`Wg.class:870`, `:905`)가 받으며 `itemAdd()`가 대문자로 맞춘다(`:589`). 오늘 서버 견본에서 `0001A0`이 인식되는 것을 확인했다(Q17).
- 상장폐지: 행을 지우지 않고 `last_seen`이 멈춘다(실측 최신일보다 오래된 19건 — 휴맥스홀딩스 10-16 · 스팩 여럿 등).
- 거래정지: 마스터에 표시가 없다. 일봉 원장 `krx_amt`에서 `vol=0` 행으로 드러난다(CLAUDE.md 급등주 규칙 12 · `qm_day_kind()`).
- 우선주: **보통주와 다른 코드**다(끝자리 5·7·9 — 예 `000105` 유한양행우 · `000087` 하이트진로2우B). 오늘 상장 기준 끝자리≠0인 코드는 114건이다(영문 코드가 일부 섞였을 수 있다 — 추정). 보통주↔우선주 연결 표는 없다. 필요한 곳은 «앞 5자리 + 0» 규칙으로 잇는다(`stock/index.php:2781-2787` — 리서치·실적을 보통주에서 빌림).
- ETF: 마스터에 없다(`market` = KOSPI/KOSDAQ 주식). `itemAdd()`가 `StockName`으로 이름을 확인하므로 **ETF는 관심그룹에 담기지 않는다**(추정 · 사슬에 ETF 표가 없음).

**Q17** 여러 종목을 한 번에 넣는 기능(붙여넣기, CSV 등)이 이미 있나.

> **답:** **있다** — 「그룹 관리 · 일괄등록」 모달(`wgroup.php:469-486`, JS `:1990-2047`)이다. **목록 붙여넣기**와 **표 붙여넣기**(마크다운 표 포함) 두 가지를 하고, 흐름은 「미리보기 → 대상 그룹(기존 또는 새 그룹) → 추가」다. CSV 파일 업로드는 없다.

- 흐름: 미리보기 `item_parse {text, group_id}` → 「표로 읽혔다」면 담을 때 `table_add {group_id, text}`. **화면이 구조를 보내지 않고 서버가 원문을 다시 읽는다.** 아니면 `item_add {group_id, codes[]}`다. 새 그룹을 고르면 `group_create`를 먼저 따로 부른다(`:2019-2045`).
- **목록**(`Wg::parse()` `Wg.class:858-890`): 줄바꿈·탭·콤마로 자른 토막(최대 300개) → 6자리 코드가 있으면 코드, 없으면 이름 정확 일치.
- **표**(`Wg::parseTable()` `:903-973`):
  - 칸 = 탭, 없으면 `|`. 마크다운 구분줄(`|---|`)과 빈 줄은 무시한다. 최대 200줄.
  - 첫 칸 = 종목: 6자리 코드가 먼저, 없으면 이름 정확 일치. 한 칸에 「`·` `,` `/`」로 여럿 적으면 같은 메모를 나눠 갖는다. 「(참고)」 접두어는 떼고 읽는다.
  - 나머지 칸 = **메모**(` · `로 이어 붙이고, 셋째 칸부터는 머리줄 칸 이름을 앞에 붙인다 — 「같이 볼 변수: 유가」). 500자까지.
  - 머리줄 = 첫 칸이 「종목」으로 시작하는 줄.
  - **한 칸짜리 짧은 줄(≤56자) = 구분행**: 앞의 `#`·공백·①~⑳·숫자·`.`·`)`를 떼어 제목으로 쓴다. 방향은 「상승·오를·인상·↑」과 「하락·내릴·인하·↓」 중 먼저 나온 쪽이고, 「불리·피해」가 있으면 뒤집는다(`:957-965`). 종목이 하나도 안 붙은 구분행은 버린다.
- 담기(`tableAdd()` `:982-1015`):
  - **이미 그룹에 있는 종목은 건드리지 않는다**(메모도 안 덮는다 · 새로 담은 종목에만 메모 · `memo IS NULL` 조건).
  - 새 종목이 없는 섹션은 구분행도 만들지 않는다. 구분행·종목은 그룹 **맨 끝에 덧붙는다**.
  - 방향이 있으면 «그 순간 그룹의 주 변수»를 `var_id`로 적는다(변수가 없으면 비워 둔다).
  - `ITEM_MAX` 30을 넘는 것은 `over`로 돌려준다. 트랜잭션은 없다.
- **표로 넣을 수 없는 것**: 기준가·기준일·변수 등록/연결·그룹 이름(그룹은 화면에서 고른다)·구분행 위치 지정.
- 글자 상한: API가 본문을 **20,000자에서 조용히 자른다**(`wgroup_api.php:187, 202` — 넘친 끝부분이 오류 없이 사라진다).

**Q19** 정렬 탭(내 순서 / 상승률순 / 기준대비순): '내 순서' 저장 방식, 정렬할 때 구분행은 어떻게 되나.

> **답:** 「내 순서」 = `wg_item.sort_no`(그룹 안에서 1..N · 구분행도 같은 줄에 선다)다. 상승률순·기준대비순은 **보기 전용**이고 저장 순서를 바꾸지 않는다. 그 보기에서는 **구분행이 사라지고 종목만 값 순으로 선다.**

- 저장: 손잡이 `⋮⋮`를 끌거나(SortableJS) Alt+↑/↓ → `item_reorder {group_id, ids:[그룹 전체 순서]}` → `renumber()`가 1..N을 다시 매긴다(트랜잭션 · `Wg.class:646-664`). 빠진 id는 원래 순서대로 뒤에 붙는다. 실패하면 원위치하고 알림을 띄운다(`wgroup.php:1021-1031`).
- 접힌 구분행을 끌면 그 섹션이 **통째로** 따라간다(`:1036-1049`).
- 보기 정렬(`viewItems()` `:737-745`): 종목만 골라 값 내림차순, 값이 없는 종목은 맨 아래, 같은 값은 원래 순서로 둔다. 끌기와 접힘은 꺼진다. 종목이나 구분행을 추가하면 「내 순서」로 돌아간다(`mineFirst()`).
- 그룹을 열 때의 기본 정렬: 보유종목·Top-Pick = 상승률순, 최근조회·내 그룹 = 기본/내 순서(`sortFor()` `:1071-1076`). 고른 정렬은 그룹 key별로 localStorage `wg_sort`에 남는다.
- 차트 격자도 같은 순서로 선다(`layoutCharts()`가 `viewItems()`를 본다).

**Q21** 삭제 정책: 하드 삭제인가, 변경 이력·로그 테이블이 있나.

> **답:** **하드 삭제**이고 **이력·로그 표는 없다.**

- `item_delete` = `DELETE FROM wg_item WHERE id IN (…)`(`Wg.class:793-801`).
- `group_delete` = `DELETE FROM wg_group` + FK CASCADE(`wg_item`·`wg_group_var`).
- `var_delete` = `DELETE FROM mv_var` + CASCADE(`mv_daily`·`wg_group_var`) + `wg_item.var_id` NULL(`Mv.class:313-319`).

- 화면의 삭제 확인: 3초 「정말?」 버튼 또는 Del 두 번(`confirm()` 금지 · CLAUDE.md:622 규칙 7).

**Q22** 일정·이벤트(실적 발표일, D-day 등)를 저장하는 기능이 시스템 어딘가에 있나. 재사용 가능한가.

> **답:** 관심그룹에는 없다. 시스템에는 셋이 있다 — **리서치의 `rs_item`(종목별 · 날짜 정밀도 포함)**이 가장 가깝지만 리서치 버전(`rs_note`)에 매달려 있다.

- `rs_item`(`classes/Rs.class:102-115`): `kind`('check'·'event'·'risk') · `d` DATE · `prec`('day'·'month'·'quarter'·'half'·'year') · `text` · `done`. `note_id` FK → `rs_note`(종목 리서치 한 버전 · append-only). 지난 일정은 리서치 «재점검» 근거로 쓰인다(`rs_stale()`). 재사용하려면 `rs_note`가 먼저 있어야 한다(FK).
- `tbl_schedule`(`classes/Schedule.class:16~` · 업무캘린더 `schedule.php`): 범용 개인 일정이다(시간/종일/기념일/할일 · 반복). 종목 연결은 없다.
- `pf_next_filing_deadline()`(`stock/index.php:2842-2860`): 다음 정기공시의 **법정 마감**(분기 45일·사업 90일) 계산이다. 저장하지 않는다. **회사별 실적 발표 예정일은 수집하지 않는다.**
- 지난 공시는 DART 수신 기록(`pf_sue_receipts()`)이 있지만 과거 기록일 뿐이다.

**Q26** 의견: 'md 붙여넣기 → 미리보기 → 적용' 임포터를 붙인다면
- 어디에 두는 게 자연스러운가 (관심그룹 `+` 메뉴 등)
- 기존 API 재사용과 직접 SQL 중 무엇이 안전한가
- 예상 위험 요소

> **답:** (의견) **기존 「그룹 관리 · 일괄등록」 모달의 붙여넣기 칸을 확장**하는 것이 가장 자연스럽다. **Wg 클래스에 새 메서드 + API action 두 개**(미리보기·적용)를 두고 서버가 원문을 다시 읽게 하는 것이 가장 안전하다 — 지금의 `parseTable`/`tableAdd`와 같은 구조다.

**1. 위치**
- 모달(`wgroup.php:469-486`)에 이미 「붙여넣기 → 미리보기 → 대상 그룹(새 그룹 포함) → 추가」가 있다. 그룹 목록 `＋` 옆에 「md 가져오기」 버튼을 따로 두더라도 같은 모달의 같은 칸을 열게 하는 편이 낫다(흐름이 둘이 되지 않게).
- 감지는 사슬로: `parseThemeMd()` → 아니면 `parseTable()` → 아니면 `parse()`. 지금 `item_parse`가 `parseTable() ?: parse()`로 떨어지는 방식(`wgroup_api.php:189-190`)과 같다.
- 「md 문서 = 새 그룹 하나」라면 그룹 이름을 md에서 읽고, 미리보기에서 «새 그룹 / 기존 그룹에 덧붙이기 / 기존 그룹 갈아 끼우기» 중 고르게 한다.

**2. API 재사용 vs 직접 SQL**
- **화면이 기존 action을 여러 번 부르는 방식**(`group_create` → `table_add` → `item_update` × N → `mv var_add` …)은 단계 사이에 실패하면 반쯤 들어간 그룹이 남는다. 호출 수도 많다.
- **직접 SQL**(CLI 스크립트·별도 PHP에서 INSERT)은 검증을 우회한다 — `StockName` 확인 · 30종목 · 50자/500자 · 고정 그룹 가드 · 이름 UNIQUE 처리. 그래서 위험하다.
- **권장**:
  - `Wg::themeParse(string $md): array`(읽기 · 무엇이 어디로 갈지 · 미인식 · 넘침 · 충돌)
  - `Wg::themeApply(string $md, array $opt): array`(쓰기)
  - API `module=wg&action=theme_parse|theme_apply`
  - 화면은 원문을 다시 보낸다(구조를 화면에서 받지 않는다 — 기존 `table_add` 규칙)
  - 안에서 `cleanName`·`cleanLabel`·`cleanBase`·`StockName::many`·`ITEM_MAX` 같은 기존 검증을 재사용한다
- md가 128KB를 넘을 수 있으면 리서치처럼 multipart 파일 조각으로 보낸다. 20,000자 컷도 임포터용으로 따로 정하고, 넘으면 «말해 주게» 한다.

**3. 예상 위험 요소**
1. **기준일**: 지금 API는 기준일을 오늘로만 적는다(Q8). md가 «기사 날짜의 종가» 같은 과거 기준일을 주려면 새 메서드가 `base_date`를 받게 해야 한다. 그 날 종가를 `krx_amt`에서 찾으면(`rs_close_on()`) **수정주가가 아니라서** 그 사이 분할·증자가 있었던 종목은 기준대비가 상수배로 틀린다.
2. **원자성**: `tableAdd`는 트랜잭션이 없다. 바깥에서 감싸면 내부 `renumber`·`bulkBase`·`transfer`·`Mv::groupSet`의 `beginTransaction()`과 부딪힌다(Q16). 새 메서드는 «트랜잭션을 쥔 쪽이 하나»가 되게 짜야 한다(예: 내부 메서드가 `inTransaction()`이면 자기 트랜잭션을 건너뛰게).
3. **외부 콜과 30초 벽**: 변수 등록은 네이버를 부른다(1개 2~4초 · 목록에 있는 cat/code만 · 등록 40개 · 그룹당 4개). 응답 30초 안에 끝나야 하므로(공유 호스팅 · 리서치·외인비가 같은 제약으로 설계됐다) DB 트랜잭션 **밖에서 먼저** 등록하고 시작하는 편이 낫다.
4. **이름 매칭**: 정확 일치만 된다(「현대자동차」 ✗ 「현대차」 ✓). md에는 **6자리 코드를 필수**로 넣고 이름은 확인용으로만 쓰게 하는 편이 안전하다. ETF는 담기지 않는다.
5. **같은 그룹 안 중복 불가**: 한 종목이 md의 두 섹션에 나오면 두 번째는 조용히 빠진다(Q7 · Q17 견본 A). 미리보기에서 말해 줘야 한다.
6. **상한**: 그룹당 30종목 · 그룹 이름 30자(UNIQUE) · 구분행 제목 50자 · 메모 500자 · 기준가 1~1억 정수. 넘으면 지금은 잘리거나(`mb_substr`) 거절된다.
7. **재가져오기 정책**: 이름이 UNIQUE라 같은 테마를 다시 가져오면 생성이 실패한다. «갱신»이면 이미 있는 종목의 메모·기준가를 덮을지(지금 `tableAdd`는 안 덮는다), md에서 빠진 종목을 지울지 정해야 한다. **이력 표가 없고 하드 삭제**라 갈아 끼우기 전에 그 그룹의 행을 JSON으로 남겨 두는 것을 권한다.
8. **구분행 판정 함정**: 기존 표 파서는 56자 이하의 한 칸짜리 줄을 전부 구분행으로 읽는다(Q17 견본 B — 제목과 표 사이의 문장이 제목을 덮었다). 방향도 키워드로 추정한다. md 스펙에서 구분행을 명시적인 표지(예: 정해진 제목 수준)로 고정하고, **방향(+1/−1)과 그 변수를 따로 적게** 하는 편이 안전하다.
9. **판정 규칙**: 트리거·무효화 가격으로 «돌파·이탈» 배지를 세우는 것은 Q18의 규칙과 부딪힐 수 있다 — 사용자 결정 사항이다.
10. **종목 순서**: 섹션 소속이 순서로 정해지므로, 기존 그룹에 «덧붙이면» 새 구분행이 맨 끝에 서고 기존 섹션에 끼워 넣지 못한다(`tableAdd`도 그렇다). 기존 섹션에 넣으려면 `sepAdd`의 `before_id`처럼 위치를 계산해야 한다.

## 자유 기재 — 임포터 설계에 영향을 줄 특이사항

1. **지금 당장 되는 최소 형식이 있다.** 채팅 Claude가 Q17 견본 A처럼 «`###` 제목(방향 단어 포함) + `| 종목 (코드) | 근거 | 같이 볼 변수 |` 표»로 내면, 임포터 없이도 오늘 그 모달에 붙여넣어 구분행·방향·종목·메모까지 담긴다. 빠지는 것은 기준가·기준일·변수 연결·그룹 이름뿐이다. 새 스펙은 이 형식의 **상위 호환**으로 잡으면 기존 붙여넣기와 충돌하지 않는다.
2. **리서치(`mode=research`)와 겹치는 영역**: 종목별 매수 구간·시나리오 가격(`rs_level`)과 확인 신호·일정·리스크(`rs_item`)는 리서치가 이미 «종목의 버전»으로 담는다. 테마 md의 «종목별 가격·일정»을 관심그룹에 새로 담으면 같은 종목에 «매수가»가 둘 생길 수 있다 — 포트폴리오·리서치 규칙이 피하려던 상태다. 테마(묶음·근거·방향)는 관심그룹에, 종목의 가격 판단은 리서치에 두는 분담도 검토할 만하다(**의견**).
3. **방향은 «변수 하나»에 대한 말이다.** 구분행의 `dir`은 `var_id`와 짝이다. 그룹에 변수가 없을 때 방향만 적으면 나중에 연결된 주 변수를 따라가 버린다(`var_id`가 빈 옛 구분행 규칙). md에 방향을 적을 거면 변수(cat/code 또는 목록의 이름)도 함께 적게 하는 편이 맞다.
4. **메모는 글 한 덩어리다**(500자). 지금 「같이 볼 변수: …」처럼 칸 이름을 붙여 이어 쓴다. 근거·출처·날짜를 구조로 남기고 싶으면 메모 안의 약속된 표기로 할지 새 컬럼으로 할지 정해야 한다.
5. **기준가 일괄은 «그 순간의 시세표 값»이다**(장중이면 장중가). 「적용하는 날 종가」를 원하면 15:50 이후에 적용하거나 `krx_amt`에서 읽어야 한다.
6. **문자 처리 함정**: `trim()`은 바이트 단위라 NBSP 처리가 한글 끝 바이트를 깎는다 — 정규식 `/u`를 쓴다(`Wg.class:908` 주석). 숫자로만 된 배열 키는 PHP가 정수로 바꾼다 — 종목코드 키는 `strval`로 다시 문자열로 만든다(CLAUDE.md:627).
7. **고정 그룹의 Top-Pick은 「보유하지 않은 ☆」뿐**이다. md의 종목이 보유 중이어도 관심그룹 행에는 「보유 N」 배지가 자동으로 붙는다 — 따로 표시할 필요가 없다.
